# AGENTS.md

## Проект

Проект: «Дневник фридайвера».

Это простое веб-приложение для ведения дневника тренировок по фридайвингу.

Изначально проект был локальным MVP на `localStorage`. Сейчас этап изменился: делаем веб-версию для тестовой группы с авторизацией и хранением данных в Supabase.

Главная цель текущего этапа:

Пользователь вошёл → добавил тренировку → запись сохранилась → открыл дневник с другого устройства → запись на месте.

## Технологии

Используем:

- HTML;
- CSS;
- JavaScript;
- Supabase Auth;
- Supabase Database.

Не используем сейчас:

- React;
- Vue;
- TypeScript;
- сборщики;
- сложный backend;
- сложную архитектуру.

## Основные файлы

- `index.html` — структура страницы, экран входа, форма дневника.
- `style.css` — внешний вид.
- `script.js` — логика приложения.
- `supabase-config.js` — подключение Supabase.
- `README.md` — описание проекта.
- `AGENTS.md` — правила работы с проектом.

## Supabase

В проекте используется Supabase:

- для регистрации пользователей;
- для входа пользователей;
- для хранения тренировок;
- для доступа к данным с разных устройств.

Таблица тренировок:

`public.trainings`

Поля:

- `id`;
- `user_id`;
- `date`;
- `type`;
- `coach`;
- `mood`;
- `training`;
- `notes`;
- `total_volume`;
- `dives`;
- `created_at`;
- `updated_at`.

`user_id` обязателен. Он связывает тренировку с конкретным пользователем.

RLS должен быть включён. Пользователь должен видеть, создавать, редактировать и удалять только свои записи.

## Безопасность ключей

В `supabase-config.js` можно хранить только:

- Project URL;
- Publishable key.

Нельзя коммитить:

- database password;
- secret key;
- service_role key;
- JWT secret;
- пароли;
- приватные токены.

## Основные поля дневника

В дневнике должны остаться поля:

- дата;
- тип тренировки: бассейн / сухая / глубина;
- тренер;
- самочувствие;
- тренировка;
- ощущения / комментарии / питание;
- общий объём;
- нырки.

Обязательные поля:

- дата;
- тип тренировки;
- тренировка;
- общий объём.

## Правила разработки

Делать всё маленькими шагами.

Не переписывать весь файл без необходимости.

Если есть несколько вариантов — выбирать самый простой и надёжный.

Не переименовывать `id` и `class`, если они используются в `script.js`.

Пользовательский текст выводить безопасно через `escapeHTML()`.

## Безопасность фридайвинга

Приложение — дневник, а не тренер и не врач.

Не добавлять советы, которые подталкивают к опасным тренировкам.

Не поощрять:

- одиночные тренировки;
- рекорды любой ценой;
- игнорирование самочувствия;
- тренировки без напарника.

Если появляются подсказки по тренировкам — напоминать про напарника, инструктора и безопасные условия.

## Проверка

После изменений проверять:

1. экран входа виден;
2. дневник скрыт до входа;
3. регистрация работает;
4. вход работает;
5. выход работает;
6. тренировка добавляется;
7. запись появляется в Supabase;
8. после обновления страницы данные остаются;
9. второй пользователь не видит записи первого;
10. мобильная версия не ломается.
